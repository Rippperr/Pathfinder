# Pathfinder career roadmap methodology

Pathfinder’s built-in role guides are designed as practical starting plans, not exhaustive checklists or promises of employment. A job title can describe different work across employers, seniority levels, and industries.

## How to use a roadmap

- **Phases** order skills from prerequisites toward applied, production, and collaboration work. The order is a suggested learning sequence, not a fixed timeline.
- **Core skills** are the broad capabilities used to build the role’s sample project and roadmap. Their progress can be tracked one skill at a time.
- **Common specializations** are useful in some stacks or sectors, but should not be treated as universal requirements. Compare these with job descriptions in the learner’s location and target industry.
- **Evidence** should be a project, lab, analysis, prototype, write-up, or other artifact that demonstrates application—not just course completion.
- Course and tutorial links are learning aids. Users should verify that a resource is current and appropriate for their experience level.

The role plans draw on primary learning and professional references where applicable: [Google’s Machine Learning Crash Course](https://developers.google.com/machine-learning/crash-course), [NIST’s NICE Framework](https://www.nist.gov/itl/applied-cybersecurity/nice/nice-framework-resource-center), [AWS Well-Architected](https://docs.aws.amazon.com/wellarchitected/latest/framework/welcome.html), [OWASP ASVS](https://owasp.org/www-project-application-security-verification-standard/), and [W3C WCAG 2.2](https://www.w3.org/TR/wcag/). They are cross-checked with official documentation and role-specific practice resources in the app.

These references provide useful foundations; they do not define every employer’s hiring bar. Pathfinder should periodically review role guides, skill names, and links against current job postings and official documentation.
